# FD-u 跨三角形验证与优化

## 验证的是什么

`python -m src fd-optimize` 验证原生 FD 表中 `u` 的跨几何预测能力。
它不验证 FL、Fzong 或截面分类，也不把 `u` 解释为已确认单位的力。
完整 pipeline 能跑通、随机点划分得分高，都不能代替这种验证。

当前默认数据为 `data/rawdata/2026-06-20/FD`：14 个工作簿、275,138 行，
按排序后的三边长度归为 4 类独立三角形。镜像、不同 Re 和文件名数字标签的
同类三角形必须放在同一折。研究入口沿用文件名中的 10/20/30 作为数值特征，
不代表已确认其物理含义或单位。

## 执行方法

在仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe -m src fd-optimize
```

默认使用本地 TabPFN v2.5 回归权重和 CUDA，同时比较 ExtraTrees。
没有可用 GPU/权重时可以只运行树模型；它与完整候选集不是同一个实验：

```powershell
.\.venv\Scripts\python.exe -m src fd-optimize --extra-trees-only
```

默认每次拟合最多 3,000 行，各候选使用相同训练样本。
内层验证每个文件约 200 行，外层测试每个文件约 500 行。
抽取完整 `(文件, x, z)` 位置，保留该位置全部 Re；为保留完整位置，
行数允许比预算略多。源数据中的重复记录保留并计数，不静默去重。
这些是抽样评估，不是对 27 万行逐点计算测试指标。

## 防泄漏流程

1. 读取源文件，记录哈希；缺列、非数值、缺失、无限值或单文件混合几何直接失败。
2. 按几何分 4 个外层折，每次完全留出一类三角形。
3. 在剩余 3 类中做 3 次留一类验证，每次用 2 类训练。
4. 对预先固定的 6 个方案计算内层平均几何 R²，选出一项。
5. 用外层的 3 类重新拟合该方案，在第 4 类上测试。
6. 同时测试固定的原始 ExtraTrees / TabPFN 基线，输出逐几何与汇总指标。

外层测试标签不参与参数、方案或随机种子选择。预处理和目标标准化只拟合训练数据。
`nested_selected` 评估的是自动选型流程，可能每折选出不同模型；它不是一个固定模型。
不能事后拿每折最高分拼接出所谓最佳外推结果。

## 本轮候选

| 方案 | 改变 |
| --- | --- |
| raw_extra_trees | 现有原始 20 个特征，200 棵树 |
| raw_tabpfn | 相同原始特征，TabPFN v2.5，1 次集成 |
| relative_extra_trees | 相对几何、位置、边距特征，加训练侧目标标准化 |
| relative_re1_extra_trees | 相对特征，按 Re 一次方及数字标签缩放目标 |
| relative_re2_extra_trees | 相对特征，按 Re 二次方及数字标签缩放目标 |
| relative_re1_tabpfn | 使用相同一次方缩放方案的 TabPFN |

相对特征保留 `bc, h, radius, re` 绝对尺度，并使用 `x/bc, z/h`、
边长比和点到边距离比等，移除来源可疑的原始面积字段。
这里同时改变了特征和目标数值尺度，不是单因素消融实验。

目标缩放采用经验假设：`factor = (Re/30)^p * (20/radius_label)`，
拟合 `u/factor`，推理后乘回 factor。Re 必须为正；p 为 1 或 2。
这不是物理定律，更不等于已经证明对新三角形有效。
TabPFN 的 `n_estimators=1` 是集成次数，不是训练 epoch；没有微调预训练权重。

## 输出与审计边界

每次运行保存在 `results/fd_extrapolation_optimization/runs/<run-id>/`，
`latest.json` 指向最近完成的运行。主要文件：

- `data_inventory.csv`：源文件哈希、行数、几何分组与质量警告。
- `config.json` / `source_snapshot/`：冻结配置、权重哈希和运行时源码。
- `splits.json`：每折训练几何及使用行数。
- `inner_metrics.csv` / `selections.json`：内层所有比较与选择结果。
- `predictions.csv`：外层预测、真实值、来源行号和工况。
- `fold_metrics.csv` / `summary.csv`：逐几何分数、几何等权均值和逐点合并指标。
- `report.md` / `outer_r2.png`：报告与图表。

本入口是保留旧数据的研究验证，不是 `system audit` 的通过凭证。
默认数据存在面积不一致、z 超出 `[0,h]`、同工况重复坐标等问题。
z 范围检查不等于完整点内三角形检查，坐标原点仍需提供者确认。
负 u 不自动当作坏值，需先确认分量/方向含义。不会擅自改值、取绝对值或裁剪。

## 结论的使用范围

4 类几何上的结果是有限的未知几何泛化估计，不能保证任意形状、尺度、Re 的远距离外推。
历史上这些几何已被分析过，本次属于带嵌套选型的研究复核，不是真正全新数据的盲测。
本命令不导出生产模型包、不更新默认模型，不会将研究结果冒充审核通过的系统模型。
特别要同时看最差三角形，不能只看 pooled R²；文件数量与目标方差会影响后者。

下一阶段应优先确认坐标/面积/单位约定，增加独立三角形类型，并预留一批从未参与
开发的新几何作为最终盲测。清理规则确定后再比较采样策略、更多上下文及集成次数，
仍只能在训练侧选择。增加同一种三角形的插值点不能代替增加新几何的独立信息。

## 代码入口

- `src/regression/optimize_fd.py`：严格读取、候选特征、目标还原、嵌套评估和报告。
- `src/regression/evaluation.py`：共享分组、抽样和指标计算。
- `src/cli.py`：`fd-optimize` 命令分发。
- `tests/test_fd_optimization.py`：组隔离、选型不依赖外层标签、目标还原及抽样预算测试。

本轮修复了共享抽样函数的索引视图问题：随机打乱位置列表前必须复制数组，
否则 pandas 的位置索引可能被原地改变，使位置与计数失配。
修复前后的测试点集合可能不同，历史分数不应直接当作同划分对照。
