# 2026-09-29 FD 数据与 TabPFN 专项验证

## 与之前实验的区别

之前使用 `data/rawdata/2026-06-20/FD`，14 个文件、4 类几何，预测单个原生 u。
本次改用 `data/rawdata/2026-09-29`，15 个基础文件、8 类独立几何，
每个文件有 24 个角度副本，共 360 个 Excel。ZIP 是重复打包文件，不重复纳入。
新增了几何类型，也改变了角度任务，不能把新旧两批的汇总 R² 直接当作同条件增益。

## 全量数据检查

本轮检查了全部 360 个 Excel、6,810,096 行旋转记录。所有角度都验证了：

`u(theta) = u(0) * cos(theta) + u(90) * sin(theta)`

最大绝对数值残差约 `7.28e-12`。这是新数据自身的确定性增强关系，
不是宣称已经确认 u 的物理含义、单位或原始坐标轴符号。
因此两个基础响应暂称 `u0`、`u90`，不擅自命名为已确认的力分量。

原始基础行数为 283,754；保留完整预测字段的 279,482 行：

- `750-400-10` 有 4 行缺少几何字段。
- `750-530-10` 有 4,268 行缺少 Re。
- 上述 4,272 行及其所有旋转副本统一隔离，原始 Excel 未修改。
- 可选的面积、旧距离列存在整文件缺失或不一致；不以全表补齐冒充测量数据。
- barycentric 坐标存在超出 `[0,1]` 的点，可能涉及原点/几何定义问题，保留并提示。
- 原始面积仍有与 `bc*h/2` 不一致的来源，需要数据提供者确认。

本审查是用于研究评估的导入检查，不是统一 `system audit` 的生产通过凭证。
没有再次执行未知单位的转换，没有裁剪负目标，没有根据预测误差剔除异常值。

## 学习信号和方案

每次默认抽取 1,500 个基础点，几何之间等额，再平衡源文件和 Re。
两份基础响应一共提供 3,000 个标量标签。

直接预测模型：将每个训练点编码为随机的一对正交角度，提供两条投影标签。
这些标签仅由训练点的 u0/u90 按已验证公式变换，信息量与两分量模型相同。
查询输入为几何、Re、文件数字标签、坐标以及角度表示。

两分量模型：两个 TabPFN 分别拟合 u0、u90，推理时按已验证关系组合。
测试点的 u0/u90 不参与预测或拟合，最终真值直接读取各角度的实际 Excel。

五个预先固定的候选：

| 方案 | 模型 | 主要改变 |
| --- | --- | --- |
| direct_e1 | 1 个 TabPFN，1 次集成 | 几何与坐标，直接角度数值 |
| direct_trig_e4 | 1 个 TabPFN，4 次集成 | 角度改为 sin/cos 周期编码 |
| components_e1 | 2 个 TabPFN，各 1 次集成 | 分别学习 u0/u90 |
| components_e4 | 2 个 TabPFN，各 4 次集成 | 分量预测增加集成 |
| components_canonical_e4 | 2 个 TabPFN，各 4 次集成 | 使用相对坐标、边长比和 barycentric 特征 |

原始特征方案保留边长、高度、角度、周长、面积、数字标签、Re、x、z。
不使用可疑的旋转距离列。面积等可选缺失值由训练侧中位数填充。
规范化特征方案不使用来源面积或旧距离列，而保留尺度和提供的相对坐标特征。
这是一组实用配方比较，不是把每一处改动都完全分离的单因素消融。
使用本地 TabPFN v2.5 回归权重，不涉及预训练权重微调；集成数不是 epoch。

## 验证协议

外层 5 折，以 8 类原始几何分组。同一几何的镜像、半径标签、Re、24 个角度
始终在同一组内，不允许旋转副本泄漏到另一侧。
内层在外层训练几何里再分 3 折，按“几何等权 + 0°/90° R² 等权”选型。
这避免较大分量主导分数。所有预处理只拟合相应训练集。

内层计算 0°、45°、90°、135° 的预测，选型使用 0°/90° 的等权 R²。
外层测试覆盖全部 24 个角度：1,507 个基础测试行、36,168 个角度标签。
测试基础行按完整 x/z 位置抽取，保留位置的 Re 行，因此每文件约 100 行，
可能略超过预算。不是对全部 681 万行计算模型测试指标。

必须同时查看：

- 全 24 角度的几何等权平均 R²、最差几何 R²。
- 0° 与 90° 各自的几何等权平均 R²。
- 每类三角形的结果，以及 pooled R² 和 Pearson r。

旋转副本不是独立实验。只有 8 类几何、一个随机种子，不能因此声称任意三角形
或远离训练范围的工况都可靠。确定性旋转处理带来的改进也不等于新增了物理知识。

## 使用方式

```powershell
# 全量检查并生成具有哈希的本地研究快照
.\.venv\Scripts\python.exe -m src fd-rotation-audit

# 将实际完成的审查目录传给评估；不使用未完成的目录
.\.venv\Scripts\python.exe -m src fd-rotation-tune --snapshot <audit-run-directory>

# 根据保存的外层预测重新生成图表和报告，不重新训练
.\.venv\Scripts\python.exe -m src fd-rotation-report --run <evaluation-run-directory>
```

审查默认使用已在本次环境安装的 `python-calamine==0.8.2` 加速读取。
其他环境可以安装该可选读取器，或使用 `fd-rotation-audit --engine openpyxl`，
后者不需要新增依赖但速度较慢。快照中的 pickle 只应加载自己生成且可信的文件；
哈希用于一致性校验，不提供恶意文件的安全保证。

审查目录包含源文件哈希、完整旋转一致性检查、数据清单、剔除行号及基础/测试快照。
评估目录包含候选配置、内层指标、每折上下文基础点 ID、逐角度外层预测、
逐几何/逐角度统计、源码快照和报告。`latest.json` 仅指向完整执行的运行。
`nested_tabpfn` 表示内层选型流程，并非每折都使用同一个固定模型。

本命令不修改生产默认模型，不导出“审核通过”的系统模型包。
物理定义和单位仍需数据提供者确认后才能进入 Fzong 合成与后续聚焦分类。
